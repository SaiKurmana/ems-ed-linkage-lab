# Limitations

> Synthetic data — for demonstration only. The results in this repository describe **the simulation**,
> not any real EMS system, hospital, HIE or population.

## The data are assumptions all the way down

- Every distribution (injury mix, ages, severity, transport rates, times, error rates, subgroup
  multipliers, failure rates) is a **configurable assumption** in `config/default.yaml`. Change them and
  the numbers change. The value is in the mechanics and the comparisons, not the point estimates.
- Data-quality problems were **injected deliberately** with higher rates for some subgroups so that
  bias could be measured. Real error patterns are different and must be measured locally.
- Deterministic UUID carry failures are **random by construction** (and sampled with exact counts so a
  regression test can check recall = configured carry rate). In reality, carry can fail systematically —
  e.g., rural or small agencies connected later — which would create subgroup gaps for the UUID too.
  `subgroup_recall.csv` therefore shows flat UUID recall partly *because of* this assumption.
- Severity, alcohol involvement, outcomes and diagnoses are generated by simple rules; they are not
  clinically validated and should not be used to infer clinical relationships.

## Linkage modelling

- Splink was trained unsupervised (EM) with standard comparisons; a real project would tune
  comparisons, term-frequency adjustments, blocking and thresholds and add clerical review.
- Precise minute-level arrival times are a powerful matching signal in this simulation. Many real
  retrospective linkages do not have reliable times; the "date-only" variant approximates that, but
  real data may be weaker still.
- The HIE matcher in Pattern B is a simple rule set, not any specific product's MPI.
- Ground truth is perfect here. Real evaluations need manually reviewed samples.
- Runtime numbers are machine-dependent and the dataset is small; they illustrate orders of magnitude only.

## Latency

- Latency curves are **pure assumptions** (deterministic links at the encounter; HIE within hours;
  probabilistic as an annual batch 18 months after the data year closes). They are labelled as such and
  configurable; they are not measurements of any program.

## Standards

- Only standards elements verified against public specs are named ([standards_references.md](standards_references.md)).
  The HL7 v2 placement of the UUID (PV1-50 with assigning authority `EMSUUID`) and the FHIR identifier
  system URI are **local conventions** that real partners must agree on.
- HL7 v2 field names were verified from the HL7 v2-to-FHIR IG and terminology.hl7.org rather than the
  licensed base standard text.
- `fhir.resources` 6.1.0 validates structure but not terminology bindings; the project adds explicit
  checks only for the required-binding codes it uses. It is not a full FHIR validator (no profile or
  invariant checking beyond the models).
- ePCR procedures are simplified text labels; NEMSIS eProcedures.03 uses SNOMED CT codes, which are
  not reproduced.

## Analyses

- The example analyses are **demonstrations of what linkage enables, not findings**. Outcome
  comparisons between EMS-transported and privately arrived patients are descriptive and confounded
  (severity, age, mechanism, access to transport).
